# What is planted in the demo dataset

The orders data is **synthetic**, generated by `data/generate_orders.py` with
seed 77. This file documents what was planted so the demo can say so out loud.
Every number below is reproduced by `data/verify_orders.py`.

**Demo question:** why did revenue change in Aug 27 – Sep 9, 2026 vs Aug 13 – 26?
**Headline:** $2,686,671 → $2,299,950 (**−14.4%**).

## Run A — broken data (`orders_broken`)

Every row of 2026-09-03 is loaded twice (1,433 rows, same `order_id`s). The
context note `2026-09-04-orders-pipeline-rerun.md` (DATA-114) is the story
behind it: the Sep 3 load timed out and was re-run by hand.

| check | result | evidence |
|---|---|---|
| duplicates | **FAIL** | 1,433 duplicate order_ids on 2026-09-03 |
| row counts | **FAIL** | 2026-09-03 is +73% vs the trailing median, \|z\| = 28.7 |
| freshness, nulls, scale | PASS | |

Health check stops the run and names the day.

## Run B — clean data

Health check passes. The worst day is Sep 4 at −16% vs the trailing median,
\|z\| = 6.2. That is the real West drop, not a data break, and it only passes
because of the relative floor described under *Spec interpretations* below.

### True cause — West shipping fee ($4.99 → $8.99 on 2026-08-27)

| | |
|---|---|
| Delta | −$292,885 of −$386,721 → **75.7% contribution** |
| Orders | 7,593 → 5,004 (−34.1%); order value flat, so volume explains 99% |
| Change point | **2026-08-27**, the same day as the pricing note |
| Last year, same windows | West +4.5%, so not seasonal |
| Drill-down | new customers −58.1%, returning −14.2% |
| West / new | orders −58.3%; every category −52% to −61%, every channel −50% to −60% |
| Verdict | **SUPPORTED + CONTEXT_LINKED** |

### Decoy — summer email campaign ends (2026-08-25, D−2)

| | |
|---|---|
| Delta | −$63,454 → **16.4% contribution** |
| Pattern | dips in every region and category, change point 2026-08-26 |
| Seasonality | this year −17.1%, last year −14.9% → 87% of this year's effect |
| Verdict | **REJECTED (seasonality)**: the same dip happens every year |

West customers skew to the app (email is 5% of West orders vs 15% elsewhere),
so the West drop barely leaks into the email lead.

### Data-driven lead — new customers

The second-largest single-dimension delta (−$233,885, 60.5%). **94% of its
lost orders are West orders**, so the overlap merge folds it into the West
finding.

On this seed it also fails consistency: outside West, new-customer revenue
barely moves (East −0.6%, North −4.4%, South +1.9%). That result is
borderline — right at the 80% threshold — so narrate the overlap merge, not
the consistency rejection.

## Why this isn't a lucky seed

An 8-seed sweep all passed `verify_orders.py`:

| | range across seeds |
|---|---|
| Headline | −10.4% to −14.4% |
| West contribution | 69% – 88% |
| Email contribution | 16% – 26% |
| Email seasonality ratio | 61% – 114% (fails above 50%) |

Seed 77 was picked because its headline is closest to "revenue dropped ~15%".

## Spec interpretations baked into `causal_crew/config.py`

These are choices the spec in CLAUDE.md leaves open or gets wrong on this data.
They need sign-off before the real health check and judge are written.

1. **Row counts need a relative floor.** Robust z alone flags the clean run
   (\|z\| = 6.2 on a real −16% day). A day is flagged only when \|z\| > 3
   **and** it is more than 25% off the trailing median (`ROW_COUNT_MIN_REL_DEV`).
2. **Seasonality compares percent changes**, not dollars, so 8% annual growth
   doesn't make last year's dip look smaller.
3. **Consistency:** within the finding's segment, split by every dimension not
   used to define it; pass if sub-segments holding ≥ 80% of baseline revenue
   move in the same direction as the aggregate.
4. **Bootstrap resamples days**, not orders. Resampling a fixed number of
   orders can't see volume changes, which is most of what moves revenue.
5. **Checks pass but contribution < 30%** → `INSUFFICIENT_EVIDENCE`.
6. **Overlap is measured on lost orders**, per "explain largely the same orders".
