# What is planted in the demo dataset

The trace data is synthetic and generated by `data/generate_traces.py`. This
file documents what was planted, so the demo can be honest about it. Every
number below is reproduced by `data/verify_plant.py`.

## Headline symptom

| | pre (Aug 28 – Sep 4) | post (Sep 5 – Sep 10) |
|---|---|---|
| Task success rate | 99.48% | 96.50% |
| Failure rate | 0.52% | 3.50% (**6.7x**) |
| Cost per successful task | $0.0763 | $0.1250 (**+64%**) |

## The true cause

Prompt **v4** ships 2026-09-05, adding ~1,400 tokens of few-shot examples to
the system prompt for `document_extract` and `qa_retrieval`. On long inputs
this overruns the context budget, output is truncated, and schema parsing
fails.

`document_extract` via `pdf_parser`:

| | v3 | v4 |
|---|---|---|
| Short docs (≤40 pages) | 99.15% | 99.16% |
| Long docs (>40 pages) | 99.20% | **72.95%** |

The interaction is the tell. Prompt version alone explains nothing — short
documents are untouched. It is v4 **and** long inputs together.

`qa_retrieval` shows the same pattern more mildly: 99.41% under v3, 98.07%
under v4, concentrated in queries with 18 or more context chunks.

**Corroborating signal:** retries do not heal these. `schema_parse_error`
appears 6,790 times against roughly 1,400 each for the transient reasons,
because a context overrun fails identically on every attempt. That is what
drives the cost per successful task up while success goes down.

## Decoy 1 — tenant Acme (the misdirection)

Acme triples volume on 2026-09-04, one day *before* the deploy, and skews
toward long documents. Aggregate success by tenant:

| tenant | pre | post |
|---|---|---|
| **acme** | 99.38% | **94.44%** |
| others | ~99.5% | ~97.8% |

Acme looks twice as bad as anyone else. Cost per successful task also starts
climbing on Sep 4 ($0.073 → $0.092), the day Acme ramped, a full day before v4.
The timeline genuinely implicates them.

Control for the cohort and it dissolves — long docs via `pdf_parser`:

| | pre | post |
|---|---|---|
| acme | 99.29% | 73.45% |
| everyone else | 99.09% | 71.64% |

Identical collapse. Acme is not the cause; Acme just has more of the traffic
that the real cause breaks. A Simpson's paradox, rejected with a number.

Two documents in `context/` state the wrong conclusion out loud — the on-call
handoff (2026-09-06) and the support escalation (2026-09-09) both blame Acme,
and support proposes rate-limiting them. Human analysts got it wrong first.

## Decoy 2 — model routing (2026-09-03)

60% of `classify` and 45% of `summarize` traffic moves to a cheaper model.
Cost per call falls from $0.0138 to $0.0044. Success rate: 99.69% before,
99.71% after. A real change with a real cost effect and no quality effect.

## Decoy 3 — weekend seasonality

Weekends carry ~38% lower volume and a 1.5 point success dip. Real, present in
the data, far too small to explain a 3 point aggregate drop.

## Decoy 4 — vendor incident (2026-09-08, 14:00–16:30 UTC)

`web_fetch` latency rises from ~3.3s to ~11s for about three hours, with a
handful of `tool_timeout` failures. Isolated to one tool path, bounded in
time, and it moves latency rather than success.
